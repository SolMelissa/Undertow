🌟 Usage.exe — the everyday stuff_ ▢ ✕

💿 Opening the Pipeline

double-click the "Hydrus Pipeline" shortcut on the Desktop. this runs Launch-HydrusPipeline.ps1, which:

  • starts Hydrus, the hydownloader daemon, and hydownloader-systray — but ONLY whichever of these isn't already running. it never opens a second copy of anything, promise.
  • drops you into a cute little text menu in the PowerShell window with four choices:
[1] Search / Discover - add new subscriptions or single downloads (opens the systray) [2] Organize / Tag - bring Hydrus to the front to tag and sort files [3] View / Browse - bring Hydrus to the front to search and view your library [4] Configure API keys - see/set Reddit and Hydrus credentials [Q] Quit - shuts down anything idle, leaves anything busy running

picking 1, 2, or 3 just brings the right window to the front — it doesn't relaunch anything. picking Q checks whether the hydownloader daemon is actively mid-download or mid-subscription-check: if it's idle, Q shuts it (and the systray) down cleanly; if it's busy, it leaves that piece running and only closes the systray. just closing the window does the exact same idle-check-then-shutdown automatically, so you never have to remember to pick Q first! Hydrus itself is never auto-closed either way — close it yourself when you're done. re-open the shortcut anytime to get the menu back without disturbing whatever's still running. 🎀

lil note: options 2 and 3 both bring forward the same Hydrus window — Hydrus doesn't have separate tagging and viewing windows, it's one client where search results, thumbnails, and the tag panel all live side by side. the menu split just reflects the two things you're most likely doing there.

🔍 Search / Discover — Adding Downloads

this is what the hydownloader-systray window (menu option 1) is for. two ways to bring content in:

✨ Single URL downloads (one-off)

use this for a single post, image, or gallery you want right now.

  • in the systray, go to the "Single URL queue" tab.
  • click "Add..."
  • paste the URL (one per line if adding several~)
  • uncheck "Start paused" if you want it to download immediately (leave it checked if you wanna review/edit it first — see below!)
  • click OK. the daemon picks it up within a few seconds.

watch the Status column: it goes from queued to either a happy green "ok" or a sad red error. click the "Logs" tab, then "Load single URL log..." and enter the row's ID to see exactly what gallery-dl did — fastest way to diagnose a failed download (see Troubleshooting down below).

important!! successfully imported files are automatically removed from the downloaded folder once Hydrus has them. if you check the downloaded folder and it looks empty, that's expected — it does NOT mean nothing happened. check Hydrus itself, or the systray's "Import history" tab, to confirm an import. don't panic!!

💞 Subscriptions (repeated / ongoing)

use this for an artist, account, or search you want to keep getting new content from automatically forever and ever.

  • in the systray, go to the "Subscriptions" tab and click "Add..."
  • pick a Downloader (the site) and enter Keywords (usually a username, tag, or search term — for sites gallery-dl supports but hydownloader doesn't have a dedicated downloader for, use downloader "raw" and put the full gallery URL in Keywords).
  • set a Check interval (how often to look for new stuff) and leave the other fields at their defaults unless you know you need something specific.

the daemon checks each subscription on its own schedule and pulls in anything new — same auto-import behavior as single URLs.

🏷️ Categorizing / Tagging

this happens in Hydrus itself (menu option 2 or 3 — same window, remember!).

  • open a search page (or use the one already open) and select one or more thumbnails.
  • the tag panel on the right side of the window shows existing tags and an entry box for adding new ones. start typing and Hydrus autocompletes against tags it already knows.
  • files downloaded through hydownloader already carry some automatic tags (hydl-import-time, hydl-src-site, hydl-sub-id, hydl-url-id, and site-specific tags depending on the extractor — artist/character/etc. where the site provides them). add your own tags on top of these freely!
  • to tag many files at once, select them all (Ctrl-click or drag a box) before typing in the tag panel — it applies to the whole selection. so efficient. so cute.

favourite tags, tag namespaces (like creator: or series:), and parent/sibling tag relationships are all standard Hydrus features — see Hydrus's own built-in help (Help menu) for the deeper tagging system if you want to build a more structured tag hierarchy.

📁 Setting Download Locations

there are two distinct "locations" here and they're super easy to mix up:

  • where gallery-dl drops files before import: the downloaded folder inside the hydownloader data directory. organized into subfolders by site (reddit, bluesky, mastodon, tumblr, pixiv, etc.) as configured in gallery-dl-config.json. files only sit here briefly — once the daemon imports them into Hydrus, poof, they're removed from this folder.
  • where Hydrus actually stores your library: Hydrus's own internal file storage, managed entirely by Hydrus (database → manage database → move media files, inside Hydrus). you generally never touch this directly — it's not a normal browsable folder of individual files, Hydrus manages it internally like a lil vault.

to change where gallery-dl saves new site subfolders (renaming/restructuring the reddit/bluesky/etc layout), edit the "directory" block under extractor in gallery-dl-config.json. to change where Hydrus stores its actual file library (e.g. moving to a bigger drive), use Hydrus's own database → manage database → move media files dialog — don't move the folders by hand outside Hydrus!! it gets mad.

🖼️ Viewing Images

  • bring Hydrus to the front (menu option 2 or 3).
  • type tags into the search box (top left) to filter, or leave it blank, add the system:everything predicate, and hit the search icon to browse your whole library~
  • double-click any thumbnail to open the full media viewer. arrow keys move to next/previous file.
  • use the sort dropdown (top of the results panel) to sort by import time, filesize, etc.
  • the tag panel on the right shows tags for whatever's currently selected/open — also where you can click existing tags to add them to your search.

🌙 Cleanly Exiting

closing everything in the right order avoids interrupted downloads and half-written database state:

  • close Hydrus first: File → Exit (or the window's X button — Hydrus does its own safe-shutdown/backup routine on close, can take a few seconds, let it finish, don't rush her).
  • close the systray: right-click its window and close it, or use its own exit option from the Menu button.
  • the hydownloader daemon runs minimized with no visible window. totally safe to leave it running in the background even after Hydrus and the systray are closed — it'll just sit idle like a good girl. to stop it too, run Stop-HydrusPipelineServices.ps1 (see Technical Maintenance).
you don't need to shut anything down between sessions if you don't want to — totally fine to leave the whole pipeline running continuously (subscriptions need the daemon running to check on schedule anyway!). the shortcut is safe to double-click anytime regardless of what's running. and remember: the launcher's Q option (and just closing its window) already only shuts down whatever's idle — no need to manually check for in-progress downloads first.
📦 Importing an Old Collection.exe_ ▢ ✕

so you've got Years™ of stuff sitting in folders — sorted by artist, by site, by "sorted (final) (final2) (USE THIS ONE)", whatever — and you want it inside Hydrus where you can actually find things again. totally doable!! this is separate from the gallery-dl/hydownloader pipeline above — that pipeline is for new downloads. this section is for the stuff already sitting on your hard drive. 💾💕

read this bit first, it matters!! Hydrus copies files into its own internal database — it never edits or deletes your originals during import, and it never touches your original folders. but the second a file goes in, Hydrus throws away its filename and folder path forever and starts tracking it only by a hash (a fingerprint of the file's actual contents). so if your folder structure or filenames mean anything — artist names, series, "good/bad" sorting, whatever — you need to turn that into tags before you import, because there's no getting it back after. this section is all about doing exactly that. 🎀

🎈 The quick way (small folders, casual stuff)

got a folder of a hundred images and don't care about preserving the folder name as a tag? just drag the whole folder and drop it right onto the Hydrus window. a dialog pops up confirming what's about to be imported — click through it, and a new page opens with thumbnails streaming in live. that's it, you're done, teehee.

heads up: this is a copy, not a move — your original folder is completely untouched and safe. you can always delete the originals later once you trust the import, or just leave them be forever as a backup. up to you!!

🗄️ The proper way (an actual collection you care about)

for anything bigger than "a folder or two," use file → import files instead of drag-and-drop — it gives you a real review window instead of just barreling ahead:

  • add your folder(s) or individual files to the queue. Hydrus will scan and list everything it found.
  • check file import options — this is where you can set min/max file size, min/max resolution, and (importantly) whether to re-import files you'd previously deleted from this same Hydrus install. that last one is OFF by default, so if you're re-importing something you once deleted on purpose, it'll silently skip it unless you flip that toggle on.
  • leave "delete original files after successful import" unchecked your first time through — it's off by default for a reason. only turn it on once you fully trust the process, and never turn it on for a mixed dump you haven't reviewed yet.
  • you've got two buttons: import now (just import as-is), or add tags before import » (set up rules first — this is the one you want, see below!!).

🏷️✨ Turning your folder structure into tags (the important part!!)

this is the actual answer to "I have a collection sorted by folder, how do I not lose that." click add tags before import » in the import files window and you'll get a filename-tagging panel with a few tricks:

  • add folders as tags — perfect for a folder-based organization scheme. if your files live in paths like Collection\Sailor Moon\Usagi\pic043.jpg, you can tell Hydrus to turn each directory level into a tag (or a namespaced tag, like series:sailor moon, character:usagi) automatically for every file under it. set this up once, preview it on a couple test files, then let it rip across the whole folder.
  • keep filename as a tag — useful if your filenames actually mean something (like artistname_character_2019.jpg) rather than being camera-roll garbage like IMG_04213.jpg. you can combine this with string-processing rules to strip junk (extensions, underscores-to-spaces, etc) before it becomes a tag.
  • add tags manually to this batch — you can also just type in flat tags to slap onto every file in the current import job, e.g. imported-batch:2026-07, so you can always find/filter "stuff I migrated in that one big push" later, separately from stuff coming in through the gallery-dl pipeline.
lil pro-tip: the panel live-previews exactly what tags a file will get before you commit anything, so play with it on 2-3 files first and check the preview looks right before pointing it at ten thousand files. much less regret that way. 🙏
real talk from the Hydrus dev himself: filenames like image.jpg or 04.jpg are useless as tags — don't blanket-enable "keep filename as tag" on a folder full of camera-roll-style names, you'll just fill your tag list with garbage. folder names describing an actual scheme (artist/series/character) are usually worth keeping; meaningless auto-generated filenames are not.

📎 Already have tags from another program?

if you used some other tagging tool before Hydrus and it can export tags to plain text — say, one .txt file per image with the same base filename, one tag per line — Hydrus can slurp those in automatically as sidecars:

  • put the images and their matching .txt (or .json) files in the same folder together.
  • drag the folder onto Hydrus like normal, but do not add the sidecar files themselves to the import list — just the images.
  • click add tags/urls with the import — this opens the sidecar panel. pick a source (which sidecar file to read and how it's separated — newline or comma, etc) and a destination (which tag service to dump the parsed tags into).
  • the panel live-previews what it parsed before you commit, same as the folder-tagging one above. for JSON sidecars it's a bit more involved (you point it at the right key in the JSON structure), but the preview makes it very hard to mess up silently.

this also works for known URLs, not just tags — handy if your old tool saved the original source link per file.

🏭 Genuinely huge collections (tens of thousands of files)

Hydrus's own docs are blunt about this: don't try to import a giant pile in a single manual job, it can choke the client. for anything really large, use file → import and export folders instead — this is the automated version and handles big jobs way more gracefully by processing them in the background over time rather than all at once.
  • set up an import folder pointed at your collection (or a subfolder of it), with the same tag-parsing options as manual import (folders-as-tags, filename-as-tag, or sidecars).
  • do a small trial run with manual import first (a few hundred files) to get your tag-parsing rules dialed in and confirm the preview looks right — then point the automated import folder at the full collection.
  • consider splitting a truly massive collection into a few smaller import-folder batches (by top-level folder, say) rather than one giant one — easier to review, easier to pause, easier to fix if one batch's tag rules were wrong.
the Hydrus dev's actual advice for big migrations: don't rush it. import a subset first (a few thousand files), leave your original folders completely intact, and live with it for a few weeks. see how often you actually go back to the old folders versus just searching Hydrus by tag. most people stop needing the folders pretty fast — but there's no need to nuke your only backup on day one. 🌙

👯 What happens to duplicate files across folders

if the same exact file exists in multiple folders (a common side effect of "sorted by artist" and "sorted by favorites" copies of the same image), Hydrus dedupes automatically during import based on the file's actual content hash — you'll only end up with one copy in Hydrus no matter how many folders it was sitting in. any tags picked up from either folder's naming scheme still get merged onto that one copy.

this only catches byte-for-byte identical files, though. if the "same" picture exists at two different resolutions, or one copy got recompressed/re-saved, those will still both import as separate files since their hashes differ — that's what the duplicate filter (mentioned in Extended Usage) is for. run it after your migration to mop up the near-duplicates the hash check couldn't catch.

🔮 Getting real tags for a folder dump that has none

if your old collection has no tags at all beyond "which folder it happened to sit in," here's the honest picture: there's no magic button that identifies every image and tags it perfectly. but a few things help a lot over time:

  • if you ever sync with the PTR (Public Tag Repository, a giant shared tag database other Hydrus users contribute to), any file in your collection that matches a hash the PTR already knows about will retroactively show up with community tags already attached — no work required on your part.
  • simple hash-based lookup tools exist (in manage tags → file lookup scripts) that can check a booru for a file by its hash/md5 and pull its tags if there's a match — fine for the occasional file, but slow and rude to a website's servers if you point it at thousands of files at once, so don't.
  • the sneaky-effective method: just keep using the pipeline above to download from artists/sources you like going forward. if a site happens to have a file you already imported manually, Hydrus recognizes the matching hash and retroactively attaches that site's tags to your existing copy. so a messy untagged backlog slowly tags itself over time just from normal use. ✨

🧹 After the import: sorting the herd

everything you import lands in your inbox first (little envelope icon on the thumbnail) until you decide to keep it. for a big migration dump, this is genuinely the fastest way to weed out the stuff you don't actually want anymore:

  • select a batch of thumbnails, then right-click → filter → archive/delete, or just hit F12.
  • this drops you into a fullscreen one-at-a-time flow: left-click or F7 = keep it (archives, removes inbox flag), right-click or Del = trash it, up arrow = skip/decide later, backspace = undo the last one.
  • nothing is actually committed until you finish the filter pass, so it's very low-stakes to go fast and trust your gut.

this is also the natural moment to set up tag siblings/parents if your old folder-derived tags are messy (e.g. "sailormoon" vs "sailor moon" vs "series:sailor moon" all meaning the same thing) — merge them once and it applies retroactively across everything you just brought in.

💡 Example flows

a folder tree organized like Artist Name\SeriesName\file.jpg

  • file → import files, add the top-level collection folder.
  • add tags before import » → add folders as tags, map the first directory level to a creator: namespace and the second to a series: namespace.
  • preview on a handful of files, confirm the namespaces look right, then run it.
  • tag the batch with something like imported-batch:2026-07 too, so it's easy to find "everything from the big migration" later if you need to fix something in bulk.

a chaotic dump with no consistent folder or filename scheme

  • don't bother with folder/filename tag parsing here — there's no signal to extract, and forcing it just creates garbage tags.
  • import as-is with a single batch tag like imported-batch:mystery-dump-2026-07 so it's at least findable as a group.
  • run the inbox filter (F12) to cut the obvious junk, then let normal tagging (and future retroactive tag matches from downloading, see above) slowly fill it in over time rather than trying to hand-tag it all at once.

files that came with their own tag export from another program

  • confirm the other program can export one .txt (or .json) sidecar per image, same base filename, in the same folder as the images.
  • drag the folder in, choose add tags/urls with the import, set up the sidecar source/destination, and check the live preview matches what you expect.
  • run a small test batch first — a few dozen files — before pointing it at the whole export, since sidecar parsing rules are easy to get subtly wrong on the first try.
🔮 Extended Usage.exe — nerd knobs_ ▢ ✕

everything above covers the everyday flow~ this section goes deeper into the properties and features that give you more control once you're past just getting things downloading, plus some concrete example flows. ✧

🎛️ Per-download properties (single URLs and subscriptions)

every single URL and every subscription has properties you can edit in the systray before (or after!) it runs. the general pattern: add new entries paused, dial in the good stuff to taste, then unpause~

propertywhat it does
Priorityhigher numbers download first. default is 0. bump up anything you want to jump the queue like it's cutting in line at the concert.
Pausedpaused entries are never processed. add something paused, edit its other properties, then unpause it — the safe way to configure a download before it fires.
Filtera gallery-dl filter expression limiting what's downloaded (file type, extension, size, etc — whatever the site's extractor exposes). see gallery-dl's own filter docs for the expression syntax.
Max filescaps how many files this URL/subscription check will pull. single URLs default to unlimited; subscriptions have separate caps for the very first check vs every check after.
Additional datafreeform text — write comma-separated tags here and they get attached to whatever gets downloaded from this URL/subscription, on top of the automatic hydl- tags.
Overwrite existing / Ignore anchorforce a redownload of files hydownloader already knows about. normally it skips anything already seen — use these two together if you deliberately wanna re-pull something.
Abort after (subscriptions only)stops a subscription check once it's seen this many already-downloaded files in a row. raise this for subscriptions on very active accounts if you're worried about missing older backlog.
Worker ID (subscriptions only)which internal thread a subscription runs on — an advanced multithreading knob. leave this alone unless you specifically need to parallelize checks across many subscriptions.

🌐 Downloading from sites hydownloader doesn't have a dedicated integration for

hydownloader recognizes URLs for a specific list of sites and turns them into downloader-plus-keywords subscription pairs. for anything gallery-dl supports but hydownloader doesn't specifically recognize, use the "raw" downloader: set Downloader to raw and put the full gallery/search URL directly in Keywords. everything else — check interval, filters, tags, etc — works exactly the same as a normal subscription. easy peasy.

⚙️ Setting defaults so you don't repeat yourself

if you find yourself setting the same Filter, Max files, or other property on every new subscription for a given site (or on everything in general), set defaults once in hydownloader-config.json instead:

  • url-defaults — applies to every new single URL added via the API/systray.
  • subscription-defaults-any — applies to every new subscription, regardless of site.
  • subscription-defaults-<downloadername> — applies only to new subscriptions for that specific downloader (e.g. subscription-defaults-gelbooru), and takes priority over -any.

use the same lowercase, underscored property names the database uses (e.g. max_files, abort_after, worker_id) — these usually match the GUI label with spaces replaced by underscores. example, in your prettiest json:

"url-defaults": {
  "max_files": 50
},
"subscription-defaults-any": {
  "abort_after": 2000
}

these only affect newly-created entries — they won't retroactively change subscriptions or URLs you already added. sowwy, no time travel here.

⚡ Quick mode — for when you need to shut down soon

Quick mode tells the daemon to skip starting subscription checks it estimates will take a while, so you're not stuck waiting on a long gallery scan right when you need your PC free. toggle it on demand from the systray, or schedule it to turn on automatically during recurring time windows via daemon.enable-quick-mode and daemon.quick-mode-time-intervals in hydownloader-config.json. you can also exempt specific subscriptions or downloaders from ever being skipped, via quick-mode-subscription-id-blacklist / quick-mode-downloader-blacklist.

👯 Multiple accounts / cookies for the same site

hydownloader supports rotating between different gallery-dl config files, cookies, and cache files based on rules (URL pattern, subscription ID, worker, or downloader) via the cfg-files-rules key in hydownloader-config.json. experimental, advanced feature — meant for cases like running two logged-in accounts on the same booru to spread out rate limits, or using a different cookie jar per site. separately (and automatically!) hydownloader also rotates plain cookies.txt files it receives via its own API (e.g. from Hydrus Companion) without you needing to configure anything, always keeping the newest one active.

📚 Organizing at scale in Hydrus

as your library grows past a few thousand files, Hydrus's own organizing tools do most of the heavy lifting:

  • tag namespaces (text before a colon, like creator: or series:) group related tags and let you filter/sort by category instead of one flat tag soup.
  • tag siblings and parents (tags → manage tag siblings/parents in Hydrus) let you merge alternate spellings into one canonical tag, or make one tag automatically imply another (e.g. a character tag implying its series). set these up once and they apply retroactively across your whole library!
  • the duplicate filter (built-in Hydrus feature for comparing and resolving near-identical/duplicate files) is worth running periodically on anything downloaded from multiple sources, since the same piece of art often gets re-uploaded across sites at different resolutions. see Hydrus's own Help menu for a full walkthrough — big enough feature to have its own docs there.

💡 Example flows

following a new artist across several sites

  • add one subscription per site the artist posts to (systray → Subscriptions → Add), using their username/handle as Keywords.
  • if they're on a platform without dedicated hydownloader support, use downloader raw with the full profile/gallery URL as Keywords instead.
  • set Additional data on each to something like artist:theirname so every file from any of these subscriptions gets that tag automatically, regardless of what the site itself provides natively.
  • leave Check interval at a sensible default (a few hours to a day) unless they post unusually often.

one-off archiving a whole gallery or thread

  • add it as a single URL, left paused.
  • set Max files to 0/blank for no limit (or a specific number if you only want the first N).
  • add any tags you want in Additional data, then unpause.
  • if you need to re-grab it later (new pages were added), re-add the same URL with Overwrite existing and Ignore anchor both on — otherwise hydownloader just skips everything it already has.

a subscription keeps erroring / redownloading the same files

  • check the subscription's log (systray Logs tab → "Load subscription log...") for the actual error — a persistent per-post error on one site is the classic cause (see archive-mode in Technical Maintenance → Common Issues & Fixes).
  • if it's rate-limiting (HTTP 429), lower how aggressively it's checked: increase Check interval, or reduce Max files (regular check) so each run pulls less.
  • if one very noisy subscription is affecting everything else, consider raising its Abort after so it stops scanning sooner once it hits already-seen files.

getting through a busy week without missing subscriptions

  • turn on Quick mode from the systray before a stretch where you might need to shut your PC down on short notice — the daemon will skip starting subscription checks estimated to run long, but will still run quick ones.
  • anything skipped this way isn't lost — it'll simply be picked up on its next scheduled check once Quick mode is off. phew!

cleaning up a library with a lot of cross-posted duplicates

  • set up tag siblings/parents first (Hydrus → tags → manage tag siblings/parents) so re-tagging survives the dedup pass.
  • run Hydrus's duplicate filter (see its Help menu) periodically to compare visually similar files and pick which copy — usually the highest quality one — to keep.
  • favor keeping the copy with the most complete tags/source info if quality is otherwise equal — Hydrus can merge tags from the discarded duplicate onto the keeper as part of resolving the pair.

📜 The Scripts

all scripts live in the same folder this page was generated in. they're all safe to re-run any time~ pinky promise.

  • Setup-HydrusPipeline.ps1 — full install/repair script. installs prerequisites via winget if missing, clones/updates hydownloader, initializes the database, patches any missing config keys, downloads the systray if needed, and starts everything. use this for first-time setup or if something needs reinstalling.
  • Launch-HydrusPipeline.ps1 — the lightweight day-to-day launcher (what the Desktop shortcut runs). starts only what isn't already running, then shows the menu.
  • Configure-ApiKeys.ps1 — shows current Reddit/Hydrus credential status (masked) and lets you set or replace either one. also reachable as option 4 from the launcher menu.
  • Stop-HydrusPipelineServices.ps1 — stops the hydownloader daemon and systray only (leaves Hydrus itself running). use this before re-running Setup if you've changed hydownloader-config.json by hand and need the daemon to pick up the new values, since editing the file doesn't affect an already-running process.
  • Create-DesktopShortcut.ps1 — (re)creates the Desktop shortcut. only needed if the shortcut gets deleted. 😱

🔑 Credential Management

two completely separate secrets are involved here, and they're easy to mix up:

secretpurpose / where it lives
hydownloader's daemon.access-keyauto-generated by hydownloader itself. used by the systray to authenticate to the hydownloader daemon's own API. lives in hydownloader-config.json. never set this by hand — if it's ever missing, Setup-HydrusPipeline.ps1 generates a fresh one automatically.
Hydrus Client API keygenerated inside Hydrus (services → review services → Client API → generate access key). used by hydownloader's importer to push downloaded files into Hydrus. lives in hydownloader-import-jobs.py (defAPIKey). set/changed via Configure-ApiKeys.ps1, option 2.

Reddit OAuth (client ID, user-agent, refresh token) lives in gallery-dl's config.json and is set via Configure-ApiKeys.ps1, option 1 — but honestly? it's optional. gallery-dl comes with its own built-in shared OAuth client and quietly uses it whenever we haven't configured one ourselves, which is normally plenty for downloading public subreddits/galleries. our own app is only worth chasing for a private (non-shared) rate limit and access to quarantined/private subs — run Configure-ApiKeys.ps1, option 2, to test whether we actually need it before doing battle with Reddit's app-creation page again.

why the app-creation page is broken, probably: as of mid-2026 Reddit rolled out a "Responsible Builder Policy" requiring manual approval before any new app gets real API access, on top of the plain ol' CAPTCHA bug on the reddit.com/prefs/apps page itself. the support-ticket route mentioned above (Reddit's help center, category Developer Platform & Data API Usage) is the documented way around both — no published turnaround time though, and small personal-use requests get rejected a lot, so it's worth describing ours as personal/non-commercial archival (not scraping, not resale) when filing it. 🎫
credentials are never re-prompted automatically. Setup-HydrusPipeline.ps1 only reports status (configured / not configured) on each run — it will NOT nag you to re-enter something you've already skipped. use Configure-ApiKeys.ps1 (or menu option 4) whenever you actually want to add or change a credential.

🚑 Common Issues & Fixes

"the client is already running" dialog in Hydrus

this happens if Hydrus is launched a second time while already running (e.g. double-clicking hydrus_client.exe directly, or calling a generic "open app" action instead of focusing the existing window). click "wait a bit, then try again" and close the dialog — do NOT click "force it" unless you're sure the old copy is actually stuck, since that can kill a healthy running instance. always use the Desktop shortcut / launcher menu to reach Hydrus rather than launching hydrus_client.exe directly — the launcher checks for a running copy first and just brings its window forward instead of starting a new one.

hydownloader daemon won't start / crashes immediately

usually caused by a config key hydownloader expects being missing from hydownloader-config.json (this happened once during setup — a KeyError on shared-db-override). re-run Setup-HydrusPipeline.ps1: it scans the config for a known set of default keys and adds any that are missing, without touching existing values (safe to re-run, won't regenerate the real access-key or overwrite anything you've configured). check the daemon's stderr log afterward if it still won't start:

C:\Users\Matt\HydrusPipeline\hydownloader-data\logs\daemon-launch-stderr.log

systray shows "Network error (status 0). Host not found"

means the systray's settings.ini has a blank or mismatched apiURL — usually because it was generated before the daemon's host/port/access-key were correctly written to hydownloader-config.json. re-running Setup-HydrusPipeline.ps1 regenerates settings.ini from whatever's currently in the config. if the daemon was already running with a stale config when this happens, run Stop-HydrusPipelineServices.ps1 first, then Setup-HydrusPipeline.ps1, so the daemon actually restarts with the corrected values instead of continuing to run with what it loaded at its last start.

note: hydownloader only actually serves HTTPS if daemon.ssl is true AND a server.pem file exists in the data folder — otherwise it silently falls back to plain HTTP regardless of the config flag. Setup-HydrusPipeline.ps1 checks for the actual file before deciding whether to write https:// or http:// into the systray's apiURL, so this should self-correct~

a single URL or subscription shows a red "http error"

open the systray's Logs tab → "Load single URL log..." (or "Load subscription log...") and enter the row's ID to see gallery-dl's actual request/response trail. a common cause is the source site rate-limiting (HTTP 429) — this happened during testing against a Wikimedia file with an unusually large revision history, where gallery-dl tried to fetch every historical revision and got rate-limited partway through. retrying with a more specific/direct URL, or just waiting and retrying later, usually resolves it. this is a source-site behavior, not a pipeline bug — not our fault, pinky swear!

a subscription keeps redownloading files it already has

hydownloader only marks a downloaded file as "seen" once a subscription check finishes cleanly. if a site has some persistent error on a specific post that a subscription hits every time it runs (or the daemon is interrupted mid-check), the check never fully finishes cleanly, so those files never get marked as seen — and the next check downloads them all over again (it won't re-save a file already on disk, but it does re-request it, wasting time and bandwidth). this is deliberate: hydownloader defaults to never marking files as downloaded on an errored check (gallery-dl's archive-mode: memory), because the alternative (archive-mode: file) risks silently skipping older backlog files instead. if one specific site is consistently affected, you can opt just that site into the faster-but-riskier behavior by adding "archive-mode": "file" to its block in gallery-dl-user-config.json. either way, the systray's "missed subscription checks" list is the place to check for anything that might have been skipped, so you can go back and manually grab it.

Reddit downloads don't work

first, double check this is actually true! gallery-dl's built-in shared OAuth client (see Credential Management above) should handle public subreddit/gallery downloads with zero setup. run Configure-ApiKeys.ps1, option 2, to test a public subreddit with --simulate (doesn't save anything) and see what actually happens.

  • test succeeds: yay, Reddit downloading already works! the only remaining blocker is registering our own app (for a private rate limit + quarantined/private sub access), which is still stuck behind Reddit's broken CAPTCHA / approval process — see Verification Summary and Credential Management above.
  • test fails with rate-limiting or a "blocked by network security" message: the shared default client is getting throttled (it's shared across literally every gallery-dl user, so this gets worse the busier Reddit is). this is exactly what our own app's private client-id would fix — worth actually pushing through registration or the support ticket for Reddit specifically, even though nothing else needs it.
  • test fails with an outright auth error: something in gallery-dl-config.json's reddit block might be malformed — check extractor.reddit for a leftover placeholder like "client-id": "PLACEHOLDER_SET_BELOW" and remove it so gallery-dl falls back to its own default.

need to fully restart everything from a clean state

  • run Stop-HydrusPipelineServices.ps1 (stops daemon + systray, leaves Hydrus running).
  • close Hydrus normally (File → Exit).
  • re-run Setup-HydrusPipeline.ps1, which will start all three fresh and re-verify the config on the way.

🔄 Updating hydownloader

hydownloader is an actively developed project on GitLab (not GitHub! — upstream is gitgud.io/thatfuckingbird/hydownloader). to update to the latest version:

  • run Stop-HydrusPipelineServices.ps1 first.
cd C:\Users\Matt\HydrusPipeline\hydownloader
git pull
python -m poetry install
  • then re-run Setup-HydrusPipeline.ps1 to restart everything and re-check the config for any new keys the update might have introduced.

hydownloader-systray is a separate repository with its own prebuilt binary releases. Setup-HydrusPipeline.ps1 currently downloads a specific pinned build; check gitgud.io/thatfuckingbird/hydownloader-assets for newer builds if you want to update it independently.

💾 Backing Up

the two things worth backing up regularly, bc data loss is NOT cute:

  • hydownloader-data\ — contains your subscriptions, download history/queue, and config. losing this loses your subscription list and dedup history (though not your actual downloaded files, which live in Hydrus).
  • Hydrus's own database — this is your actual media library plus all tags. use Hydrus's built-in database → backup database feature rather than copying files by hand, since Hydrus's storage isn't a simple flat folder structure.
